## 1. Что это за продукт

**Лавка** — публичная страница дела по постоянному адресу, устроенная
сразу для двух читателей: человек читает глазами, машина забирает
разметку. Внутри страницы живёт агент, который отвечает посетителям
**строго по записанным фактам** и доставляет заявки владельцу на почту.

Лавка собирается **разговором за пять минут, без сайта**: человек
разговаривает с агентом как с живым собеседником, слева на глазах
заполняется его лавка, в конце — ссылка на витрину и секретная ссылка
правки. Второй вход — **чтение сайта** — сохранён за кнопкой
«У меня есть сайт»; он в ~20 раз дороже и нужен не всем.

### Чего продукт не делает и делать не должен

- Не пишет ничего, чего владелец не говорил. **Пробел честнее выдумки** —
  правило проходит через весь код и заперто тестами и сторожами.
- Не выдумывает отзывы и оценки; `aggregateRating` не выводится никогда.
- Не обещает видимость в чужих ИИ, не показывает проценты понимания.
- Наружу — слово «лавка». «Паспорт» — внутреннее (схема, код, `/gb-debug`).

## 3. Маршруты

Страницы: `/` → `/start` (разговорный вход, двухпанельный с первой
секунды) · `/start?site=1` (чтение сайта) · `/t/<slug>` (лавка + агент) ·
`/t/<slug>/edit?t=<токен>` (правка + блок «Заявки») · `/gb-debug?token=…`.

`POST /api/onboarding`, ветвится по `action`. Разговорный вход:
`talk` · `talkAnswer` · `talkFinish`. Путь через сайт: `intro` · `mirror`
· `scan` · `extract` · `nextStep` · `answer` · `retrySite`. Общие:
`publish` · `updateFact` · … · `deleteShop` (владелец сносит свою лавку
по секретной ссылке). Плюс `/api/chat*`, `/api/lead`,
`/api/lavka/<slug>.json`, `/api/health`, `/robots.txt`, `/api/debug/*`.

## 4. Вход «с нуля» — рамка ПОСЛЕ разговора, а не до

Три фазы (`src/lib/freeTalk.ts` + talk-действия в
`src/app/api/onboarding/route.ts`):

1. **Свободный разговор.** В промпте ни слова про слоты. Сначала фаза
   понимания (`readFirstLine`, `src/lib/interviewer.ts`): дело / статус /
   не дело / отказ / растерянность. После первого содержательного ответа —
   **карта блоков** (собирает код): «Блоков 6: чем занимаешься · для кого
   · как проходит работа · цены и сроки · примеры работ · как начать
   работу», применимость блоков решает тип дела (`businessType.ts`).
   Слева — панель лавки настоящей вёрсткой витрины
   (`talkPassport.ts` → `renderPassport`), блоки заполняются на глазах.
   Прогресс «блок 3 из 6», подтверждение «Записал: …» — всё строит код.
2. **Невидимый разбор.** Транскрипт уходит в тот же [GEN], что читает
   сайты (`generateCardFromTranscript`, `cardFromFacts.ts`) → карточка
   двенадцати слотов, те же контракты и приёмка.
3. **Точечный добор.** Один-два вопроса про недостающее — тем же
   механизмом, что добор на экране правки.

Конец решает судья сбоку («хватит/мало» после каждого хода) плюс кнопка
«Собрать лавку сейчас»; жёсткий потолок — 15 реплик.

### Сторожа кодом — важнее промптов

Каждый поставлен после живого провала; в коде рядом написано, какого.

- **Заголовок не выдумывается** (`titleGuard.ts`): слова
  заголовка/подзаголовка сверяются с репликами владельца по стемам.
  Все стемы его — публикуем молча; появились новые — флаг
  `INVENTED_TITLE`, вопрос «назовём лавку так?», и до ответа лавка
  **не публикуется**.
- **Возражение стирает факт**: «нет, не это», «не консультации», «я не …»
  — оспоренный блок чистится на панели немедленно и переспрашивается.
- **Должность ≠ дело**: «я руководитель региона» — честный ответ кодом,
  что лавка собирается под дело; класс `status` в классификаторе +
  `looksLikeStatus` на случай промаха модели.
- **Без лести**: открывашки («Круто!») и оценочные реакции на статус
  («Это большая ответственность») срезаются (`stripFlattery`).
- Валидатор реплик интервьюера (`interviewSpeech.ts`): предпосылки,
  рассогласование, двойной вопрос, канцелярит, повтор, реплика без
  вопроса — брак → одна регенерация → запасной вопрос.
- Применимость слотов к типу дела, неповтор закрытого, «короткое
  отрицание — не факт», готовность — всё кодом (`interviewer.ts`).
- В JS `\b` не видит кириллицу — границы слов в регулярках пишутся
  явно. На этой грабле проект стоял трижды.

### Тестовые лавки

Лавка приёмочного прогона создаётся с `test: true` → адрес получает
префикс `gbtest-` (`testShop.ts`): noindex всегда, в robots закрыта целым
префиксом, любой будущий каталог/sitemap обязан фильтровать по
`isTestShop`, живёт 24 часа (первый заход после срока удаляет насовсем).
**Приёмочные прогоны не оставляют следов в проде.**

## 5. Чтение сайта (второй вход)

Трёхпроходный конвейер (`siteReader.ts` / `siteReadUnified.ts`): целевая
компания → атомарные утверждения с цитатами → отбор кодом → судья →
сборка с инспекциями. Краулер: 15 страниц, глубина 2, бюджет 40 с,
Jina Reader как обход бот-блока. Повторное чтение бесплатно —
кэш `site_reads` (миграция 015). **SSRF-защита `netGuard.ts` не
удаляется**; для e2e есть поимённая щель `GB_ALLOW_PRIVATE_HOSTS`
(точное имя хоста, в проде переменная не задана).

## 6. Модели и деньги

Роли разведены (`modelPlan.ts`, обоснования замерами лежат рядом):

## 7. Карточка, витрина, машинный слой

- **Карточка v2** — двенадцать слотов (`card.ts`), контракты
  (`sanitizeCard`), приёмка (`cardAccept.ts`), применимость слотов к
  типу дела (`businessType.ts`: у эксперта нет каталога, у стартапа —
  цен). Источники полей подписываются честно: `owner` / `site` /
  `compiled`.
- **Правило индексации** (`cardIndexing.ts`): лавка без подтверждённого
  владельца не индексируется — мета страницы + `robots.txt` из базы.
- Витрина — вёрстка дизайнера (хендофф GB LONDON 10);
  `passportMarkup.ts` сгенерирован из `design/london10/**` и руками не
  правится. JSON-LD, `/api/lavka/<slug>.json` — из тех же данных.
- Экран правки `/t/<slug>/edit`: очередь работ, добор пробелов, блок
  «Заявки» сверху.

## 8. Агент лавки и заявки

Семиблочный промпт (ROLE/PROCEDURE/CONSTRAINTS/TONE + контекст), речь —
поставка куратора дословно; восемь правил речи продублированы кодом
(`speechCheck.ts`). Заявка посетителя уходит **письмом на почту из
слота 12** с флагами `LEAD_DELIVERED`/`LEAD_NOT_DELIVERED` в трейсе и
блоком «Заявки» на экране правки. **Resend и телеграм сняты с повестки —
не трогать.**

## 9. База

Supabase, только REST с сервис-ключом. Таблицы: `tenants`, `facts`,
`cards` (карточка v2 одним JSON, ключ правки), `conversations`,
`messages`, `traces`, `leads`, `site_reads`. Миграции `sql/001…015`,
идемпотентные, запускаются владельцем в SQL Editor — **SQL владельцу
отдаётся текстом в чат**, файл в `sql/` создаётся всё равно.
Состояние разговора «с нуля» — `tenants.question_plan.interview`.

## 10. Проверки перед пушем — и правило моста

```bash
npm run typecheck
npm test          # юниты, включая дословность канона
npm run build
npm run e2e       # 4 пути целиком на моках сайта, базы и модели
./bridge.sh       # после мержа — обновить этот документ И опубликовать в gb-bridge
```

**Красный путь = не мержим.** Каждое изменение — тестом. Ход агента или
генерация без трейса — баг. Дефект, найденный и закрытый внутри захода,
наверх не выносится — он остаётся в коммитах и тестах.

## 11. Правила работы, которые лучше не нарушать

1. Промпты и тексты наружу поставляет куратор — дословно, свои
   формулировки не сочиняются (`prompts.ts`, `onboarding.ts`, `copy.ts`;
   дословность заперта тестами).
2. Пробел честнее выдумки; сторожа кодом, не увещеванием.
3. Ключи никогда не попадают в чат и в коммиты. Vercel руками не трогать.
4. Никаких новых механизмов, пока пути не зелёные.
5. Спека части 3 (MCP-адаптер) и 4 (лимиты) — не начинать.
6. Ссылки в переписке — только полные, с доменом.

## 13. С чего начать первым днём

1. `npm ci && npm run typecheck && npm test && npm run build && npm run e2e`.
2. Открыть `/start`, написать «продаю мёд с пасеки», пройти разговор до
   ссылок, открыть лавку и экран правки. Пятнадцать минут — вся картина.
3. Прочитать `src/lib/freeTalk.ts` и talk-действия в
   `src/app/api/onboarding/route.ts` сверху донизу: комментарии
   объясняют не «что», а «почему», с живыми провалами, из-за которых
   код стал таким.
