## Подвох, который надо знать до настройки

Каналов доставки в коде **два**, и они работают по-разному:

| канал | кому уходит | работает для посевной карточки? |
| --- | --- | --- |
| почта (Resend) | на `tenant.owner_email` — адрес ВЛАДЕЛЬЦА карточки | **нет** |
| Telegram | в один фиксированный чат — наш | **да** |

`deliverLead` шлёт письмо только если у карточки есть `owner_email`. У
посевной карточки владельца ещё нет, поля нет — и письму просто некуда
идти, даже с правильным ключом.

**Поэтому для живой проверки на посевной карточке (как просили в задании)
нужен Telegram. Одного `RESEND_API_KEY` для этого не хватит.**

Ставить стоит оба: почта — рабочий канал на будущее, когда владельцы
заберут карточки; Telegram — то, что заработает сегодня и на посеве.

## А. Telegram — заработает сразу, в том числе на посевных

**Переменные:** `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — нужны обе,
одна без другой канал не включает.

1. Открыть в Telegram https://t.me/BotFather → отправить `/newbot` →
   придумать имя и username → БотFather ответит строкой вида
   `123456789:AAH...` — это значение `TELEGRAM_BOT_TOKEN`.
2. Написать своему новому боту любое сообщение (иначе он не сможет
   написать первым).
3. Открыть в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — подставив токен из
   шага 1. В ответе найти `"chat":{"id":123456789` — это число и есть
   `TELEGRAM_CHAT_ID`.
4. https://vercel.com/gb16/gb-agent/settings/environment-variables →
   Add New → имя `TELEGRAM_BOT_TOKEN`, значение из шага 1 → отметить
   **Production, Preview, Development** → Save. Повторить для
   `TELEGRAM_CHAT_ID`.
5. **Redeploy нужен.** Vercel → Deployments → верхний → «⋯» → Redeploy.
   Переменные читаются на старте функции, без передеплоя старая сборка
   их не увидит.

## Б. Почта — для карточек с владельцем

**Переменные:** `RESEND_API_KEY` (обязательна) и `LEAD_FROM_EMAIL`
(необязательна, по умолчанию `Grand Bazar <onboarding@resend.dev>`).

1. https://resend.com/api-keys → Create API Key → права Sending access →
   скопировать строку вида `re_...`.
2. Туда же в Vercel, имя `RESEND_API_KEY`, все три окружения, Save.
3. Redeploy, как выше.

Отправлять с адреса на своём домене — https://resend.com/domains →
Add Domain → прописать DNS-записи; после подтверждения задать
`LEAD_FROM_EMAIL` вида `Grand Bazar <lead@ваш-домен>`. Без этого письма
уходят с `onboarding@resend.dev` и чаще попадают в спам.

## Как проверить, что получилось

https://gb-agent-git-main-gb16.vercel.app/api/health

Смотреть поле **`checks.leadEmail`**. Сейчас `false`. После ключа Resend
и передеплоя должно стать `true`.

**Важно: это поле показывает ТОЛЬКО ключ Resend** —
`leadEmail: Boolean(process.env.RESEND_API_KEY)`. Настройка Telegram его
не меняет, и по нему проверить телеграм-канал нельзя. Отдельной проверки
на Telegram в `/api/health` нет — это дефект, записан в очередь, сам не
чинил.
