**Серверные правила — кодом:**
- **§7.1 склейка**: сообщения с паузой < 2.5 с — один ход. После вставки
  сообщения короткий грейс и перечитывание диалога: ход не последний —
  вливается в пачку (`MERGED_TURN`), модель отвечает один раз на всю пачку.
- **§7.2 дедуп**: дабл-клик того же сообщения → прежний ответ без нового
  вызова модели (`DUPLICATE_TURN`).
- **§7.3 пустой ввод**: точка/символ → «Слушаю вас.» константой без модели;
  второй раз — молчание.
- **§7.4** `ILLEGAL_REQUEST` — флаг в телеметрию, диалог штатно.
- **Раскладка кодом**: «ytn» читается как «нет» ещё до модели — отказ поля
  с репликой «Понял — «нет», пропускаем.»; длинная латиница уходит в модель
  с приложенным транслит-прочтением.

**Попутный улов живого прогона:** модель ссылалась на факты ключами
(`terms.pricing`) вместо id — правдивый ответ уходил в брак. Ключ теперь
резолвится как честная ссылка на факт; несуществующее — по-прежнему брак.

## 2. UX-баг чата: лента прижата к низу — закрыт

Причина: чат-экраны росли вместе со страницей (`min-height`), и новое
сообщение вытягивало страницу вниз — под кромку. Теперь чат-экраны прижаты
к вьюпорту, скроллится сама лента; после каждого сообщения она держится у
низа, **кроме случая, когда человек отлистал вверх читать историю** — тогда
его не дёргает, пока сам не вернётся к низу.

Проверено настоящим браузером на длинном диалоге (`tools/scrollcheck.mjs`):

```
✓ лента длинная (1271px в окне 454px)
✓ после 10 сообщений лента у низа (scrollTop 817 из 817)
✓ отлистал вверх — не дёрнуло вниз (scrollTop 0)
✓ вернулся к низу — снова прижимает (scrollTop 1011 из 1011)
```
