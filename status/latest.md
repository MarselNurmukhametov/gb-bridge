# Статус · 01.08 · Блок 1: карточка через веб-поиск — сходится с эталоном, краулер уходит в фолбэк

## Что сделано (за час, как задано)

Путь владельца воспроизведён кодом, краулер не использовался вообще:
один вызов OpenAI Responses API с инструментом web_search и человеческим
промптом «Составь бизнес-карточку компании. Сайт: …». Результат
раскладывается в контракт факта (assertions с источниками: сайт → website,
зеркала ЕГРЮЛ → registry, прочее → third_party) — модуль
`src/lib/webSearchReader.ts`, приёмка `tools/websearch-card.mjs`.

## Приёмка против эталона владельца (metahim.tech) — построчно

Полный отчёт рядом с эталоном: `e2e/websearch-card.md`. Итог финального
прогона — **1 расхождение из 15 проверок**:

- **Услуги: 6/6 → 5/6** по смыслу (шестая — «обработка и анализ данных» —
  между прогонами то входит, то нет).
- **Контакты: телефон ✓ почта ✓ адрес ✓** («время работы» в финальном
  прогоне модель не включила — в двух предыдущих было ✓).
- **Реквизиты: юрлицо ✓ ИНН 5042161136 ✓ ОГРН 1225000144390 ✓** — со
  ссылкой на реестровый источник (РБК Компании, данные ЕГРЮЛ); в
  контракте лежат как `registry` → `independently_verified`.
- **«Что не подтверждено»: ✓ 5 пунктов** (проекты, клиенты, команда,
  цены, патенты) — раздел строит КОД из карты пробелов, не модель.

## Что выяснилось по дороге (важно для решения)

1. **Дело в модели поиска.** gpt-4o с web_search реквизиты не достаёт и
   путает телефон; **gpt-5** ходит и по сайту, и во внешние источники —
   уровень эталона. Поиск — gpt-5, упаковка в словарь — gpt-4o.
2. **Один вызов дышит.** Пять прогонов: реквизиты пришли в двух из пяти
   сами; починено кодом — если карточка без ИНН, код делает точечный
   добор вторым человеческим вопросом (тот же веб-поиск, не краулер).
   Мелкие поля (часы работы, шестая услуга) плавают между прогонами —
   это цена «одного человеческого запроса» без наших схем.
3. Цена вопроса: 40–160 с и 8–24 ₽ за карточку (у краулера было ~22 с
   и ~3 ₽, но без реквизитов и с 124 сырыми разделами).
